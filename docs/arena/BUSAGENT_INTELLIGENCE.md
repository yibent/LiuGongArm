# BusAgent 自主规划与任务队列

Panda 使用 `robot.intelligence` 节点管理用户目标。简单指令直接生成动作；复杂目标先由规划模型给出方案和完成条件，再由监督模型根据实际观察展开、修改剩余步骤。两个角色可以使用同一模型，也可以独立配置。

## 执行链路

`intent.created → robot.intelligence → plan.proposed → plan_validator → loop_router → execution_coordinator → device_adapter → Arena`

动作完成、失败和视觉观察通过 BusAgent 事件回传。MySQL 保存目标、动作状态和待发布事件；状态更新与事件写入在同一事务内完成。正常连续动作不逐步调用 LLM；仅在语义检查点、失败或阶段结束需要判断时调用监督模型。一个 Panda 同时执行一条物理命令。

新操作默认追加 FIFO 队列，不替换已有工作。明确的暂停、取消、恢复、修改请求和前端控制按钮可以管理队列。每条动作有独立的 Bus task ID 和稳定的控制器 command ID。BusAgent 重启先核对 Arena 命令账本；如果仿真本身已重启，会识别运行实例变化并保留未知结果，用户恢复后依据新场景重规划，避免向新账本重发旧动作。连续未取得任务进展的恢复达到配置预算后，显示原因并保留任务；归位等准备动作不会重置恢复预算。

正常观察检查点不消耗失败恢复预算。监督模型可以继续已有待执行动作，也可以调整剩余动作；阶段摘要不能覆盖原始目标与完成条件，只有用户明确修改目标才会更新它们。

## 自主选环与图像

模型根据任务、当前持物、视觉置信度、失败原因和能力目录选择工具，没有规定必须遍历每个模型：

- `perceive` 的 `vision_mode=fast`：YOLOE、SAM2 分割和光流路径。
- `vision_mode=slow, slow_provider=sam3`：直接使用 SAM3 概念定位，或快环失败后重新定位。
- `slow_provider=florence2` / 场景 `describe`：可选的本地描述与零样本候选。默认 `inventory` 用 YOLOE 批量候选；Florence 按需加载，不在启动或普通抓放中强制调用。
- `grasp`、`pick_place`、`place_held` 的 `mode=auto/basic/enhanced`：自动级联、简单算法或增强模型。普通抓放内部已做定位，不必先重复识别。

SAM2 的职责是提示分割与跟踪，不能假设其具有 SAM3 的开放词汇识别能力。跟踪请求使用 `tracking=true`。检测清单可能不完整，多视角候选不能直接相加作为计数。

默认不给规划/监督模型附图。模型需要时调用 `read_image(camera,purpose)`，由服务直接读取本次 JPEG；Bus 记录用途、帧序号和时间，不传图片、mask、点云。过期帧不会用于当前检查。模型请求图片无需再询问用户。物理结果以 Arena 评测为准，图片不能替代抓取/释放确认。

执行对象来自视觉观测的标签与 RGB-D 几何。内部物理实例编号只关联执行和评测，不能作为视觉提示。抓取成功保留夹爪坐标系中的 RGB-D 几何，在持物确认有效时直接复用，避免夹爪遮挡导致重复分割失败。独立放置从当前持物继续，桌面自由放置用 `destination={label:"table",selection:"free_space"}`。

## 插空放置与视觉指代

LLM 负责选物品、支撑物与偏好；RGB-D 几何节点确定落点和方向。执行参数示例：

```json
{"skill":"place_held","params":{"destination":{"label":"yellow tray","selection":"free_space","preference":"left"},"mode":"auto"}}
```

`selection=auto` 默认尝试空位；`free_space` 明确要求空位；`center` 是明确的中心放置请求。`preference` 支持 nearest、any、left、right、near、far、center、compact。左右和远近按观察相机投影解释。算法从可见水平支撑面去除高于支撑面的障碍，分别检查物品受支撑和夹爪避障，夹爪可伸过支撑边缘但该空间必须已被观察且无障碍；再结合间隙搜索多个位置及 0°、±45°、±90° 朝向，按偏好和移动距离排序。窄小且无障碍的柱顶在 auto 下仍可按物理支撑允许物体悬边，不因为装不下整个夹爪投影而统一拒绝。

视觉节点给对象及候选区域生成 `obs:<观测编号>:<相机>:<候选序号>`。LLM 可通过 `target.ref`、`destination.ref` 和 `destination.region_ref` 传递选择，必须原样复制实际引用，整次观察的 request_id 不能作为实例引用。命名托盘自动插空不需要 region_ref。SAM2/光流重新定位当前帧；跟踪丢失则用原图 YOLOE 视觉提示重新寻找，不能直接执行旧像素框。跨场景引用需重新观察。这些引用来源于画面，与配置资产名称无关。

增强放置先选择空闲区域，再让 AnyPlace 生成候选，并根据实际放置轮廓筛掉不适合该区域的候选。当前空位算法覆盖可见的水平支撑面；不是全机械臂扫掠碰撞规划器，也未实现任意姿态插入、悬挂和高精度装配。

## 速度、监督与恢复

连续明确步骤依靠执行事件推进，不在每个动作前后等待监督 LLM。运动期间通过已有持物相对位姿和夹爪开度检查滑落，连续多个观测失去夹持才停止；当前持物确认使用仿真中的物体位姿，未接入真实机器人关节力矩/六维力传感器。GraspGenX 和 AnyPlace 负责生成候选，系统负责物理验证和恢复，不能把候选得分当作执行成功。

失败反馈包含类型、阶段、持物状态和建议恢复。抓取或运动失败后 auto 才升级增强；basic 严格只运行快算法。放置规划已确认无可见空位时，直接反馈目的地问题，不先调用昂贵模型抓起物体。模型候选在接触前 IK 不可达时可就地换候选，最多尝试 3 个，取消、失去持物或实际接触后的失败不会盲目复用。已经拿住物品的恢复保留夹持，继续 place_held；失败恢复与普通检查点分别计数。

已实现后台提前规划：当前简单抓放的最后一次释放动作运行时，准备队列里下一条明确且独立的任务。物理动作仍串行；只有前一条实际成功、持物已释放、仿真实例和任务版本未改变，才采用提前计划。失败、取消、修改使准备结果作废。依赖当前动作结果、需要新图像或复杂阶段决策时仍在观察到结果后规划；不声称所有监督已异步化。界面显示后台准备、计划就绪、已采用或需按新状态规划。

规划/监督默认 Qwen Plus，启用 Qwen Max 作为 API 超时或失败时的备用。图片上下文只会切到支持图像的备用模型，同一轮中已经失败的提供方不会在后续工具轮重复调用。默认单次请求 20 秒、整轮规划 60 秒、6 次工具轮，均可通过配置调整（前端提供时间与备用模型设置）；这限制一次无进展推理的成本，不限制用户任务队列长度。推理停止、服务重启和暂停会保留已完成步骤。

历史视觉结果完整保留在 Bus/MySQL，模型上下文仅保留当前候选、置信度、必要的新观察及结果摘要，同一类别同一相机的旧帧去重，但同帧多个实例不会合并。一次现场快照中视觉上下文从 37,500 字符减至 3,599 字符；此数字只表示该快照压缩效果，不等同于所有任务的时延降幅。

## 前端与模型配置

工作台右上方新增“任务队列”和“模型设置”。队列显示方案、完成条件、具体工具、执行反馈及模型调用次数，可以暂停、恢复、取消和调整待执行任务顺序。

模型配置支持 Qwen、GLM 和 OpenAI 兼容接口，规划/监督分别选型，可设置地址、模型 ID、API Key、图像支持和思考开关。支持连接测试和显式读图测试。保存后下次请求生效。

当前用户提供的专属 Qwen 地址通过 `/models` 返回 `qwen3.7-plus` 和 `qwen3.8-max`；默认两角色均用 `qwen3.7-plus`，关闭思考以减少等待。GLM 配置入口已提供，未提供其独立密钥前不启用，也不声称已验证其多模态接口。

GLM 5.3 Flash 的思考不能关闭，界面对应显示固定开启，并提供低／高／最高强度，默认低强度以优先速度。适配依据：[官方接口说明](https://docs.z.ai/guides/vlm/glm-5.3-flash)、[官方模型卡](https://huggingface.co/zai-org/GLM-5.3-Flash)。这项提供方约束不会限制任务类型。

私密配置位于 `BusAgent/backend/.local/intelligence.json`，管理令牌位于同目录 `admin-token`，权限为 0600；两者均被 Git 忽略。前端 GET 不返回密钥，密钥输入留空会保留已有值。管理令牌仅用于修改模型配置和调用测试接口。语音识别/合成已改用用户提供的 Qwen Key，保存在云端私密 `.env` 的 `DASHSCOPE_API_KEY`，不写入源码。模型设置页修改规划配置不会自动更换语音 Key。

API：

- `GET /v1/tasks`：完整队列状态。
- `POST /v1/tasks/control`：`{action,id?,instruction?}`，action 为 pause/resume/cancel/retry/up/amend；修改目标使用 amend + id + instruction。
- `GET /v1/model-config`：不含密钥的设置。
- `POST /v1/model-config`：`{settings,token}`。
- `POST /v1/model-config/test`：`{profile,token,vision?}`。

环境开关 `BUSAGENT_ROBOT=franka_panda` 默认启用；`BUSAGENT_INTELLIGENCE=0` 可恢复旧指令入口。`BUSAGENT_INTELLIGENCE_CONFIG` 可指定私密配置文件路径。云端继续由现有 Supervisor 启动 BusAgent，新增数据库迁移随启动自动执行。

## 能力边界与验收

这次升级提供自主规划、队列、反馈监督、选环和按需读图；它不能替代尚未实现的物理技能。当前 Arena 能力目录仅声明已有技能。工业例子中的精确格位、端面朝向纠正、满箱判断和搬运堆叠，以及悬挂/插入，仍需对应感知与执行模块并逐项仿真验收，不能因 LLM 能写出步骤就认为已经实现。

测试记录见同目录 `busagent-intelligence-validation.json`。接口故障注入与真实仿真验证分别记录，避免把测试替身结果当成物理执行成功。

本次真实仿真中，独立持物放置一次模型调用完成；两个零件连续换托盘并检查，三次模型调用完成，全程约 67 秒，其中两次物理抓放各约 23 秒。这是单次实测，不是复杂工业任务的成功率或时延保证。浏览器文字下达任务、队列、设置和按需读图均已测试。更换语音 Key 后，浏览器收到 7 段合成音频；合成的“现在在做什么”经 16 kHz PCM 送入真实 ASR、BusAgent，得到正确转写和任务状态回复。尚未进行真人麦克风声学验收。

升级后的最新单次实测：两条独立抓放指令共 58.7 秒，各一次模型调用；第二条约 5.9 秒的规划与第一条运动重叠，释放确认后采用。另一次在已有齿轮的黄色托盘内插空放置圆环，快算法 27.1 秒完成，落点与选择位置相差约 2 mm，并通过支撑与稳定性验证。这些分别是独立样本，不能作同任务前后性能对比或成功率统计。
