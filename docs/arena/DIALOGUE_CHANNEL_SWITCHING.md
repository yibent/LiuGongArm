## 请求与切换规则

- 一次对话生成只请求当前渠道一次，不在同一次生成里尝试备选。接话和最终回答分别属于实际 API 请求。
- HTTP 错误、网络错误、请求超时、空文本响应计为失败；成功一次清零。
- 用户打断、结果抢先返回导致的接话取消、语音合成失败不计入模型失败。
- 当前渠道连续第三次失败后，将下一个备选持久保存为实际使用渠道；后续请求使用新渠道。新的渠道同样遵循三次失败规则。
- 不轮询旧渠道，不自动恢复默认渠道，到最后一个备选后不循环。
- `roles.dialogue` 保存用户选定的默认渠道；`fallbacks.dialogue` 保存顺序；`dialogueRouting` 保存实际渠道、失败次数、配置代次和切换状态。配置文件权限为 0600，并通过原子替换写入。
- 同一主机中的配置修改和请求结果串行写入。旧渠道及旧配置代次的迟到结果不会污染新渠道计数。普通保存、陈旧页面携带的运行状态不会撤销自动切换。

## 前端

模型设置中提供「即时回答默认渠道」和可选择、上移、移除、添加的备选渠道。界面单独显示实际使用渠道、连续失败次数与备选耗尽提示，并周期刷新运行状态而不覆盖编辑中的配置。

更换默认渠道后保存会切换到所选默认渠道；「保存并切回默认渠道」允许恢复原默认并清零计数。后端对应经过原管理令牌认证的模型设置接口，增加 `resetDialogue: true`，运行状态仍由服务端维护。
