# Q8 后续闭环测试（进行中）

日期：2026-09-07。完整 Q8 尚未通过。组件成功不代替 BusAgent 自主完成装箱、搬箱和叠放。

## 本轮修改

- `locate_object` 使用小上下文 VLM 按图像关系选择对象，同帧 SAM2 框选后直接获得物体、长轴或格网引用。候选标签不再作为“箱内、横倒”等关系已确认的证据。图片仅在显式调用工具时进入这次模型请求。
- 端点约束贯穿 grasp、pick_place、place_held。横倒件按观测长轴斜向夹持，再经 Arena 全姿态 IK 旋正；倒置件进入模型抓取候选。自由偏航按旋转距离排序，真实关节限位导致停滞时提前尝试其他候选。
- 持物参考保存闭爪后的实际宽度。闭合空爪、夹持宽度明显丢失及相对位置漂移均不能报告继续持物；抬升、转正运输、下降阶段连续监测。
- 格位释放等待实际工具姿态到位，侧壁接触不代替落座。已释放但评测失败时，将原始失败交给监督，不立即重抓旧引用而掩盖失败原因。
- 评测用的点云在原始观察时绑定到物体坐标系，独立于控制使用的持物预测点云。抓取推动物体之后，不能再把旧点云错误地绑定到新物体姿态。
- 格网识别从实际规则隔板峰中排除弱遮挡峰，不补造缺失隔板。相机改为 1280×960，并调整主、侧视角提高端面像素数。
- VLM 选框优先结构化工具返回，同时接受带说明文字的唯一有效 JSON。主视角未确认目标时，自动用另一视角复核；每次 SAM2 使用对应相机的原始快照，不能混用框和图像。观察预算耗尽前保留一次只提交计划的推理。

## 场景有效性修正

原始横倒件与格板在初始化时互相穿插，导致抓件时连箱带起。仅把横倒件初始高度由 24 mm 改为 70 mm，让重力把它自然落在隔板上（稳定后约 47 mm）。零件、料箱、格板尺寸、质量与任务不变。未改变摩擦、未焊接或传送物体来完成动作。该修正必须在复现时一并使用。

## 监督成本与人工监督模式

repair-6 自然语言测试选对了箱内横倒件，但规划将抓取与放置拆开，仅在后续 place_held 中传朝向约束，抓取未获得最终朝向需求。物体成功抬升，却无法用当前抓法完成低位放置；监督多次重试格位和观察，215.76 s 后 blocked。

已返回的 17 次模型调用累计输入 335,332 tokens（其中 API 报告缓存命中 204,672），输出 3,329，图片输入 7,212。监督节点占 11 次、272,350 输入 tokens。以上为 API usage 字段汇总，非账单金额，未包含对话节点及超时请求的潜在账单。

用户要求暂时关闭监督 LLM 后，云端持久配置 `supervisorEnabled=false`，保留规划器、按需视觉及物理评测。前端模型面板有对应开关。阶段检查或失败停留在 review 等待人工核验，不触发监督模型；不会因为关闭模型就自动宣布任务成功。后续由测试者查看画面/执行记录继续测试，必须与自主 BusAgent 验收区别记录。

人工恢复记录：第一次直接桌面暂放仍失败（26.39 s，AnyPlace 无合适候选，保持持物）。随后通过已有 Arena 手动全姿态接口抬高 4.07 s、转向 6.12 s，夹持仍有效，再用普通 `place_held` 在桌面空位成功释放（19.91 s，物理支撑与稳定通过）。没有传送物体或重置场景，也未调用 Qwen 监督。该恢复验证表明应增加换姿/重新抓取阶段，不能只对原抓姿反复更换目标格。

随后 `manual-regrasp-repair.json` 用同一零件的当前图像重新抓取，40.95 s 扶正入第一排第一格，独立几何检查通过。这一段在失败现场连续恢复，没有重置仿真。

执行与视觉修复：

- 快环在真实目标周围的 RGB-D 点云中比较 Panda 张开手指的进近方向，按观测占据数量及腕部转动距离选偏航。使用机械臂几何，不使用场景资产名称；这是局部手指路径排序，不宣称整臂碰撞规划已经完成。
