## 修改

- 明确且完整匹配的复位、夹爪开合通过 Bus 的 planning.requested → intelligence.decision.proposed 路径快速生成动作，不调用规划 LLM。动作仍使用控制器能力目录、既有执行与反馈链路。否定、条件、复合任务和未匹配表达继续交给规划器。
- 进度、复位状态、可明确关联到已有任务的进度追问，直接读取任务账本并回到对话节点，不创建新执行任务、不等待模型渠道。未识别的任务表达继续允许模型处理。
- 明确要求场景概览时，直接用当前 RGB-D 同步帧做一次短视觉请求；不先用完整工具目录询问是否需要读图。复杂关系识别和抓放规划仍使用原工具路径。
- 状态、动作进展、推理错误由对话节点原样交付事实并走原 TTS，避免再次推理改写执行结论。普通对话与复杂查询保留回答模型。过时的只读查询结果不抢占更新的用户提问。
- 新动作因全局暂停等待时明确解释原因。首页展示“任务队列 · 已暂停”；有明确 pending 步骤的恢复直接继续调度。全局恢复不自动重试一个历史 blocked 测试，显式指定任务的重试仍可用。
- 执行列表和任务计数不包含纯交互目标，原始 Bus/记忆归档保留。兼容旧记录中缺少 interaction 标志的无步骤问答。当前会话和活动任务优先进入工作上下文，最新任务优先展示。

## 本轮架构修改

1. 同一个规划智能体新增精简入口：只带当前请求、持物、能力名称和少量相关任务。普通有限动作一次模型请求就提交计划；不再必经“分类模型→完整规划模型”。复杂任务才展开完整工具上下文。
2. 应答、状态查询与执行分流。常见语气词和进度查询不生成目标；其他查询由语义入口识别，并在后续工具层禁止查询创建动作或管理运动队列。状态交付使用最新账本，不让对话模型改写成成功。
3. 其他会话的静止旧任务只作为可检索历史，不自动进入当前执行上下文。队列管理只向明确的管理请求开放。当前请求在上下文末尾单独重申，历史要求不能当作新命令。
4. 普通“任选一个、放到空位”允许 target.selection=any、destination.instance_selection=any。独立异步准备作业在机械臂可执行时取新集合，绑定实际视觉引用；格网容器选已观测空格，普通支撑面保持既有 free_space 路径。显式 ref、cell_ref、region_ref 不被替换。
5. 本地类别检测未定位到目标时，先重新定位已学习的视觉引用；仍失败才做一次短上下文视觉选框，再交 SAM2/几何处理。局部失败不从头重规划整个任务。旧框必须通过新观测验证，不能直接执行。
6. 准备作业不占住调度循环；暂停、取消、修改和重启可取消准备，应用结果前核对目标版本。物理运动继续沿用原控制器，未修改机械臂运动参数。
7. 允许模型同轮请求多个独立工具，减少逐对象的 LLM 往返；有依赖的工具仍顺序处理。模型备选渠道、对话模型及语音协议保留。
8. 直接视觉调用发布含实际时间、模型、快慢环结果的元数据事件；前端保留独立视觉与动作轨道、父子关系，合并对应结果，避免重复卡片。图像张量不经过 Bus 事件。
